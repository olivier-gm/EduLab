Proveedor y modelo de IA

El proveedor seleccionado se usa para informes, glosarios y lectura de archivos. Los cambios se aplican a las siguientes generaciones.

Solo para cuota agotada, servicio caído o error desconocido (no para claves inválidas ni contenido bloqueado). Necesita la clave de los dos proveedores. Cada vez que se usa queda un aviso en el registro del servidor.

Gemini directo

{{ key_status['gemini'] }}. La clave completa no se muestra.

OpenRouter

Más razonamiento mejora la calidad pero gasta más tokens (y dinero) y tarda más. Se le suma margen al límite de salida para que el texto no se corte. Si el modelo no admite el nivel elegido, OpenRouter rechaza la petición.

{{ key_status['openrouter'] }}. La clave completa no se muestra.

Con el fallback activado, si el ligero falla se reintenta con el modelo ligero del otro proveedor. En OpenRouter el ID puede ser de cualquier proveedor (proveedor/modelo) y terminar en :floor (precio más bajo) o :nitro (más rápido).

El modelo ligero corrige las mayúsculas y tildes del título y los subtítulos antes de generar (una llamada muy corta): conviene uno más rápido y barato que el principal. Se usa el del proveedor activo, o el del otro si el fallback entra en acción.

Con la búsqueda activada, el desarrollo y la bibliografía usan información actual de internet. Si la búsqueda falla (por ejemplo, sin cuota) se genera igual sin ella: el desarrollo avisa al usuario y la bibliografía usa referencias de IA; en ambos casos queda un aviso en el registro del servidor. En OpenRouter se solicita búsqueda nativa; la búsqueda se cobra aparte del texto generado.
